# 标签显示顺序与“固定口味候选”提示移除

## 目标与范围

用户在 2026-10-18 提出两项界面要求：

1. 成品站点里多处以成排标签铺开显示（筛选 chips、客人卡片、详情头部、表格标签列等），料理和酒水标签都要按用户附图“食谱Tag / 酒水Tag”的顺序排列——**左到右、上到下**。
2. 删除各界面红框标注的“固定口味候选，不保证本次点单评价（说明）”提示。

本轮只改攻略表站点的呈现层与构建入口：模板内联脚本、`ryotei_ui.js`、`ryotei_navigation.js`、`ryotei.css`、构建报告说明与两个回归脚本；不改数据基线、原始工作簿/JSON、推荐规则或游戏逻辑，不动同级其他项目。进入时仓库已有大量未提交改动，本轮在其上增量修改，未回退、提交或推送。

## 附图顺序与落位规则

附图“食谱Tag（包含）”共 40 项、“酒水Tag（包含）”共 22 项，首项“不变”在数据中不存在（不是本项目使用的标签），不进入顺序表。数据中的派生/特殊标签按游戏 Tag 序号插位：

- 料理：`昂贵 → 实惠 → 大份 → 肉 → 水产 → 素 → 家常 → 高级 → 传说 → 重油 → 清淡 → 下酒 → 饱腹 → 山珍 → 海味 → 和风 → 西式 → 中华 → 咸 → 鲜 → 甜 → 生 → 招牌 → 适合拍照 → 凉爽 → 灼热 → 力量涌现 → 猎奇 → 文化底蕴 → 菌类 → 不可思议 → 小巧 → 梦幻 → 特产 → 果味 → 汤羹 → 烧烤 → 辣 → 燃起来了 → 酸 → 毒 → 忧郁之毒 → 天罚`
- 酒水：`昂贵 → 便宜 → 无酒精 → 低酒精 → 中酒精 → 高酒精 → 可加冰 → 可加热 → 烧酒 → 清酒 → 鸡尾酒 → 西洋酒 → 利口酒 → 啤酒 → 直饮 → 水果 → 甘 → 辛 → 苦 → 气泡 → 古典 → 现代 → 提神`
- 动态流行标签（`流行喜爱（动态）`、`流行厌恶（动态）`）始终排最后；顺序表未收录的标签保留原有先后并排在已收录标签之后，不丢弃。

说明：附图本身不含料理价格标签以外的大份/毒，也不含酒水价格标签；这些标签是站点按游戏原生口径派生并实际显示的，因此按同一 Tag 序号规则插位（料理价格标签在附图第 2–3 位；酒水价格标签排在酒水段之前，与料理处理一致），不是遗漏。

## 实施

### 标签顺序

- `脚本/guide_template_ryotei.html`：新增 `FOOD_TAG_ORDER`、`DRINK_TAG_ORDER`、`TAG_ORDER_RANK` 与 `sortTagsForDisplay()`；`tagHtml()` 渲染前统一排序，`tagSuggestions()` 的筛选建议改用它（原先按 `localeCompare` 排）。
- 标签来源仍为原字段：客人喜好/厌恶料理、喜好酒水、菜品标签、冲突标签、食材标签、加料补足标签、酒水标签、命中喜好均只在显示时排序，筛选匹配、推荐集合与计数逻辑未改。
- `脚本/ryotei_ui.js`：客人卡片不再单独做“动态殿后”排序（由 `tagHtml` 统一处理）；表格标签单元格的“前 3 项 + N”摘要先排序再截取，避免摘要与展开内容顺序不一致。
- `脚本/ryotei_navigation.js`：命中喜好（`命中喜好` 字段）按同一顺序输出，使表格、展开的“客人与命中”文字一致；`verify_full_recommendations.cjs` 为独立核对注入同一实现，集合比较仍与原生审计双向一致（9,202 条、命中标签逐对相同）。

### 提示移除

- 删除 `ryoteiRecommendationNotice()` 及四处调用：客人详情推荐料理/推荐酒水工具栏、备菜料理页、客人酒单页；同时删除 `.recommendation-note` 样式。
- 客人详情“特殊判定”原因与普通客人卡片提示保留（与红框提示不是同一条）；页面正文不再出现“固定口味候选”。

### 构建与回归脚本

- `脚本/build_html_ryotei_avatar.py` 的构建报告 `changes` 更新：移除“显著区分固定口味候选”的过期描述，补充标签顺序与提示移除两条。
- `脚本/verify_ryotei.cjs`：新增附图顺序（含派生/动态落位）、统一渲染、筛选建议改序、提示已移除的断言；原“备菜页必须包含固定口味候选”断言改为必须不包含。
- 新增 `脚本/调试/verify_tag_order_2026-10-18.cjs`：只读活成品，用本机 Edge（Playwright）核验 7 个页面的筛选 chips、表格标签单元格、详情头部、两个详情页签、客人/普通客人卡片的顺序，并确认各界面无提示元素。
