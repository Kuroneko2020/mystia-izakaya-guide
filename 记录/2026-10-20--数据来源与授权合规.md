## 核查（2026-10-20）

用 GitHub API 对两个仓库逐文件比对，方法为取本仓库 `中间数据/*_LIST.json` 的 `name` 序列，与上游 `master` 分支 `app/domain/data/**/records.ts` 中各常量的 `name` 序列求交集：

- BEVERAGE 50/50、INGREDIENT 70/70、COOKER 41/41、DECORATION 19/19、CLOTHES 28/28、NORMAL_GUEST 47/47、SPECIAL_GUEST 69/69 全部命中；
- FOOD 199 条中 198 条命中，差异为「黑暗物质」（本仓库）↔「飞刀串串烧」（上游）；
- 上游仓库内不存在同名 JSON，酒水数据在 `app/domain/data/beverages/records.ts` 的 `BEVERAGE_LIST` 常量中；字段（id/name/description/tags/dlc/level/price/from）与取值逐项一致，判定为同一数据的 JSON 再序列化，而非文件级复制；
- 上游为 AGPL-3.0；本仓库此前无 LICENSE 文件，README「数据来源」表虽已把该上游列为「主数据」（2026-10-11 提交 `9774f56` 已存在，早于 issue），但缺少许可证传递、逐文件来源与素材例外说明。

结论：issue 指认属实；缺的是许可证与逐文件来源层面，不是署名是否存在。
