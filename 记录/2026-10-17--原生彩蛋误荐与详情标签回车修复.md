# 原生彩蛋误荐与详情标签回车修复

## 目标与范围

用户从成品 `2610151241` 反馈：射命丸文喜欢家常，但游戏中不喜欢真·海鲜味噌汤，要求查原因并排查所有客人的同类问题；同时要求客人详情搜索标签后按回车加入选择清单，支持拼音和缩写。

本次维护原攻略表离线 HTML，不涉及同级玻璃图鉴项目。进入时仓库已有多轮未提交改动，本次仅在其上增量修改，未回退、提交或推送。未启动游戏、修改游戏、存档或配置，未安装依赖；未修改原始工作簿、原始 JSON 或站点数据基线。

## 结论：区分已证实问题与现场未知

### 文与真·海鲜味噌汤

- 游戏 4.4.0e 提取物中，料理 37 的固有标签为水产、汤羹、家常、清淡。
- 射命丸文 4000 固定喜好包含家常，固定厌恶仅西式，料理彩蛋引用为空。这个组合确实只命中家常。
- 未找到文与这道汤的专属厌恶、家常被覆盖或地点改变此规则的原生证据，不能给它伪造黑名单，也没有提高所有推荐的命中阈值。
- **用户当次“不喜欢”的确切原因未证实。** 本轮没有当次料理/酒水点单、实际加料、当天流行、厨具/buff、版本/模组等现场证据。不能将“未满足点单”或“负面流行”从可能性升级为现场结论。

原生普通特殊客人评价路径会分别检测菜、酒是否满足当前点单：两边均未满足时最高 1，仅一边满足时最高 3，两边均满足时保底 2；其余喜好、厌恶及特殊覆盖继续影响结果。因此固定口味候选并不等同本次点单高评价，单固定命中也不等同坏评。普通客人按具体菜酒下单，不能把特殊客人的点单标签算法机械套给普通客人。

### 全量核查与确定修复

独立检查 106 位客人 × 163 道菜，共 17,278 个组合；原生→上游、上游→站点基线、独立默认成餐→基线共 2,227 项选定字段比较，0 差异。该结果不代表游戏现场验收或全部语义零偏差。

旧逻辑只匹配固定喜好及厌恶，**没有消费原生 `guestFoodEasterEggData` 的特殊评价覆盖**，造成以下四条实际误荐：

| 客人 | 料理 | 旧固定命中 | 原生特例 |
| --- | --- | --- | --- |
| 古明地恋 | 无意识妖怪慕斯 | 甜、梦幻 | 直接最低评价 0 |
| 绵月丰姬 | 蜜桃红烧肉 | 果味 | 直接最低评价 0 |
| 普通客人月人 | 蜜桃红烧肉 | 不可思议 | 直接最低评价 0 |
| 犬走椛 | 疯帽子茶会 | 大份 | 主料含可可豆，评价最高 1，并停止续单 |

绵月依姬同样有蜜桃红烧肉禁忌，但原本不在固定喜好候选中，不额外计为删除。犬走椛的原生字段名是 `chocolateId`，实际 ID 5000 中文名是**可可豆**，不是据字段英文猜出的“巧克力”；基础配方和额外加料都触发。现有椛加料建议没有可可豆，新增规则仍防止以后重新进入。

穷尽 13 个客人引用、11 个唯一彩蛋资产；其中 3 个纯闲聊资产继承的 `foodId=0` 不作为食物禁忌。正向彩蛋不冒充固定喜好，也未据此扩大候选策略。

修复前固定料理候选 9,206 条；单命中 5,430 条，涉及 105 位客人；仅命中家常 542 条，涉及 32 位客人、34 道菜。**单命中统计只是潜在误解范围，不是错误数。** 修复后料理候选 9,202 条，且仅减少上表四条；酒水匹配 2,812 条保持不变。文仍有 113 条料理候选，真汤仍仅命中家常。

## 实施

### 原生规则统一接入

- 新增 `脚本/extract_guest_food_rules.py`：从已核原生 profile、类型和反汇编证据提取规则，以 ID 联结显示名；不手填客人—菜品关系。未知类型、引用覆盖不全或分支证据不满足时中止；输出独占创建，不覆盖已有文件。
- 新增 `中间数据/GAME_GUEST_FOOD_RULES.json`：4 个直接料理条件、1 个食材条件；机器推导 10 个受影响客菜条件供独立回归。保留来源相对路径及 SHA-256。
- `build_html_ryotei_avatar.py` 校验规则 schema 与来源哈希，独立内嵌 `guest-food-rules`；原始 `app-data` 保持逐字符不变。
- `ryotei_navigation.js` 的共用匹配索引增加菜品/主料特殊判定排除；详情、备菜表、按物品合并及今晚覆盖榜统一受益。食材精确匹配，不能把“可可豆酱”等相似词当作同一食材。
- 加料解析复用同一食材禁忌及适用菜禁忌，避免把不适用料理的加料示例重新引入。
- 客人详情、普通客人卡片显示特殊判定原因。料理和酒水列表增加可折叠的“固定口味候选，不保证本次点单评价”说明。物品图鉴保留全部菜，未恢复集中配餐功能。

### 客人详情标签回车

旧主列表已有键盘处理，但详情只绑定 `input` 和鼠标标签事件，缺少 `keydown`。

- 详情料理与酒水委托键盘事件，复用主列表的标签解析/提交处理，避免两套键盘语义漂移。
- 中文、完整拼音、首字母可回车加入标签；清空普通查询以便继续叠加，多个标签同时满足。
- 已选词再次回车不取消也不重复；空搜索框 Backspace 删除最后一项。
- 输入法组合态及 keyCode 229 不提交，防止确认中文时误选。
- 歧义缩写不再按排序静默取第一项，保留搜索词并提示用完整拼音或点标签。
- 只刷新列表、计数和 chips，保持输入节点；换客人清过滤、排序与历史阅读恢复保持。
