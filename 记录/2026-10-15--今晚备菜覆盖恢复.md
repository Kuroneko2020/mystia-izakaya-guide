# 2026-10-15：恢复“今晚备菜覆盖”参考

## 用户要求与判定

用户要求：“之前好像是可以在物品图鉴页选择开店地点，然后统一展示当前开店地点可能来的人以及对应的需要准备的料理吧，恢复这个功能”。

判定：该功能是 2026-10-08 评估（`记录/2026-10-08--备菜推荐功能可行性评估.md`，结论“仅用内嵌数据做覆盖聚合即可”）并于 2026-10-14 随配餐一起实现的**今晚备菜覆盖**（1407 的“我的备菜清单”内“料理/酒水覆盖参考”+“查看覆盖客人”）。本轮上午随“集中配餐及其衍生功能整体移除”一并删除，现按用户要求**以只读形式单独恢复**，不带回配餐工作台、钱包账本、自定份数清单、常用搭配等其余被删功能。

页面归属说明：用户说的“物品图鉴页”实为营业图鉴的**备菜表三页**（备菜料理/推荐酒水/加料参考）——“今晚开店”选框一直在这三页的筛选侧栏顶部，覆盖面板随选框联动；物品图鉴（菜谱/食材/酒水）自始没有地点选框。面板挂在这三页的内容下方，默认折叠，摘要显示“今晚备菜覆盖 · N 位可能来客”。

## 实现

| 对象 | 内容 |
| --- | --- |
| `脚本/guide_template_ryotei.html` | 新增 `#night-preparation` 折叠面板（挂工作区底部）；`ryoteiPrepCoverage(kind)` 纯函数聚合、`ryoteiPrepCoverageList(kind)` 榜单渲染、`ryoteiRenderPrepCoverage()` 面板渲染；`switchTab`/`renderTab` 两处挂点随页签与地点变化刷新 |
| `脚本/ryotei.css` | 面板网格挂载（备菜表页 col2/row3）、两列覆盖榜单式、620px 单列回退；榜单内部滚动上限 420px（小屏放开） |
| `脚本/verify_ryotei.cjs` | 新增模板静态断言（面板存在、覆盖榜标题、口径备注必含“不是每晚必来/不含店面等级限制与出现概率”）与 `ryoteiPrepCoverage` 聚合单元 VM（地点圈人、稀客/普客分桶、覆盖数排序、全部地点不漏人）；一处旧单元 VM 补 `ryoteiRenderPrepCoverage` 空实现（该 VM 只测路由行为） |
| `脚本/build_html_ryotei_avatar.py` | 构建报告 changes 补记本轮恢复条目 |

数据口径：只用既有内嵌基线数据，**不恢复 `MEAL_DOMAIN_DATA.json` 或任何配餐模块**。聚合逻辑：`ryoteiVisitsPlace` 圈定当前“今晚开店”地点的可能来客（因幡帝各地保留），从 `buildMealIndex()`/`buildDrinkRecIndex()`（全量静态口味匹配明细）汇总每道料理/酒水覆盖的客人，稀客/普客分桶计数，按覆盖总数→价格→名称排序。实现中修复了本人初版的一个缺陷：`.filter(ryoteiVisitsPlace)` 会把数组下标当作 `place` 第二参传入导致漏人，已改为显式单参包装并被新增单元测试覆盖。

面板内容：口径备注（“不是每晚必来、最高评价或备货份数，也不含店面等级限制与出现概率”）、可能来客名单（全部可点进客人详情，链接带地点参数）、“需要准备的料理/酒水”两列覆盖榜（每行：物品链接、N 稀客 · M 普客 · 价格、折叠“查看覆盖客人”列出具体客人）。榜单为**全量展示不截断**（与站点“候选保持全量”一致）；1407 当年为 top-8 摘要形态，如需改回摘要可一行调整。
